You are a senior product engineer and UX architect.
You are improving an on-chain FX hedging platform called BlockFinaX.

Your task is to restructure both the website and in-app experience to increase clarity, trust, and usability.
Do not generate marketing fluff. Produce implementation-ready output: copy, layout structure, component logic, and UI behavior.

⸻

OBJECTIVE

Make the platform:
	1.	Instantly understandable
	2.	Numerically concrete
	3.	Trustworthy for financial users
	4.	Clean and minimal

Assume the user is financially literate but not technical.

⸻

PART 1 — HOMEPAGE RESTRUCTURE

Generate a full homepage structure including:

1. Hero Section

Provide:
	•	Headline (1 sentence, plain English)
	•	Subheadline (1–2 lines)
	•	Primary CTA
	•	Secondary CTA

No abstract Web3 language.

The message must clearly explain:
	•	What the user protects
	•	From what risk
	•	How fast/simple it is

⸻

2. Who This Is For Section

Create a 3-card layout:

Card 1: Importers exposed to FX depreciation
Card 2: Exporters receiving foreign currency
Card 3: Crypto traders managing volatility

Each card:
	•	1-line pain
	•	1-line solution

⸻

3. How It Works Section (4 Steps Max)

Generate step-by-step content:

Step 1: Select currency pair
Step 2: Choose strike and duration
Step 3: Pay premium
Step 4: Automatic settlement

Keep explanations under 20 words each.

⸻

4. Example With Numbers (MANDATORY)

Create a realistic USD/GHS example:

Inputs:
	•	Strike: 30.00
	•	Premium: 4%
	•	Duration: 30 days
	•	Hedge amount: $10,000

Show:
	•	Scenario A: Rate moves to 33
	•	Scenario B: Rate stays at 29

Calculate and clearly show:
	•	Premium paid
	•	Payout
	•	Net outcome

Display it in table format.

⸻

5. Credibility Section

Generate structured content blocks for:
	•	Collateral model (1 short paragraph)
	•	Oracle source explanation
	•	Smart contract audit status placeholder
	•	Clear statement on risk disclosure

No hype language.

⸻

PART 2 — APP IMPROVEMENTS

Generate implementation instructions for:

A. Hedge Purchase Flow

Before confirmation:
	•	Show max loss
	•	Show max payout
	•	Show breakeven rate
	•	Include payout preview calculator

Explain UI behavior clearly.

⸻

B. Tooltips Required

Create tooltips for:
	•	Strike
	•	Premium
	•	Settlement
	•	Volatility buffer (if used)

Each tooltip under 25 words.

⸻

C. Risk Confirmation Modal

Before transaction signing:
Include:
	•	Summary of exposure
	•	Total premium
	•	Worst-case outcome
	•	Checkbox: “I understand this is a financial contract”

⸻

PART 3 — DOCUMENTATION STRUCTURE

Generate a docs page structure including:
	•	How contracts work
	•	Liquidity model (who takes opposite side)
	•	Collateralization explanation
	•	Oracle mechanics
	•	Extreme volatility scenario handling
	•	FAQ (5 questions)

Keep everything concise and technical.

⸻

DESIGN RULES
	•	Remove vague phrases like “empowering financial freedom”
	•	Avoid buzzwords
	•	Avoid heavy animations
	•	Emphasize numbers
	•	Use clean layout
	•	Keep homepage under 6 sections

⸻

Output format:
	1.	Homepage copy
	2.	App flow improvements
	3.	Docs structure
	4.	UI logic explanations where needed

Be precise. Avoid filler. This is financial infrastructure.
